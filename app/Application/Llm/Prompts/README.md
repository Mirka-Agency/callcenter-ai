# AI prompts

This directory owns the application’s AI prompt definitions and message/context builders. Processing services call these classes; provider adapters send their output.

| File | Responsibility | Main editing points |
|---|---|---|
| `PromptBuilder.php` | Full call-analysis instructions, response example, policies and user context | Individual policy methods for behavior; `systemPrompt()` for composition; `contextPrompt()` for context |
| `SpeakerRolePrompt.php` | Map Soniox speaker IDs to agent, customer or unknown | `system()` for role rules; `user()` for JSON context |
| `SonioxContext.php` | Soniox recognition context for mixed Persian/English speech and known organization metadata | `instructions()` for transcription guidance; `build()` for structured context |
| `TranscriptTriagePrompt.php` | Classify short transcripts as real, personal or no conversation | `system()` for rules; `user()` for context |
| `TranscriptionPrompt.php` | Legacy audio-transcription prompts and fallback speaker-turn labeling | `instructions()`, `speechApiPrompt()`, `whisperPrompt()`, `speakerTurnSystem()`, `speakerTurnUser()` and `userTurn()` |

`TranscriptionPrompt` retains its existing transcript/continuation helpers. Soniox normally supplies segments, so the legacy transcription instructions are not part of the current Soniox + Luna path. Soniox recognition options belong to `app/Infrastructure/Transcription/SonioxClient.php`; its structured `context` is built here by `SonioxContext`.

Soniox context requests that recognizable English words and technical terms remain in English when spoken, without a fixed vocabulary list or translation rules. It includes the current call organization's title (up to 200 characters) and business context (up to 1000 characters), omitting blank values. Those limits keep background context small. It does not prescribe speaker counts or supply guessed customer names. This guidance is not a guarantee of recognition accuracy. Analysis language rules keep explanatory prose in natural Persian while allowing source English terms, names, identifiers and direct evidence quotes to retain their original spelling.

## Editing

1. Change the relevant prompt definition here. Keep response keys and field types compatible with their consumers.
2. Check related policies and examples in `PromptBuilder`; the final analysis system message combines them. Instructions spread across these methods can still conflict.
3. Check post-processing before changing the intended behavior. In particular, `app/Support/CallCoachingRules.php` normalizes extension/department referral items into `next_actions` rather than promised callbacks.
4. Run the relevant prompt, triage, speaker-mapping and provider tests. Compare rendered messages when a change is intended to preserve behavior.
5. Deploy the code and restart queue workers. Use `php artisan queue:restart`, or `php artisan horizon:terminate` for Horizon. Rebuild configuration cache if configuration or the coaching catalog also changed.

`LLM_*` environment values select the provider/model and transport; they do not hold prompt text. Coaching skill keys and labels come from `config/coaching.php`.

The current environment resolver uses the code-defined base prompt. `PromptBuilder` still supports explicitly supplied legacy database prompt versions; that compatibility is unchanged. Existing stored analyses and speaker mappings are not automatically regenerated by a prompt edit.

The language, callback, factual-grounding, deduplication and coaching-scoring policies in `PromptBuilder` and post-processing now keep summaries and explanations in natural Persian while preserving source English terms, keep `follow_up_suggestions` strictly for explicit agent callback promises (moving extension/department referrals without a promised callback to `next_actions`), separate agreed actions from coaching suggestions, require observable evidence for criticism, forbid voice-tone/speed judgments on text-only transcripts, consolidate repeated rules, and calibrate coaching/dimension scores by call type and observable score bands.
